# MEDIQ Data Dictionary

This document provides detailed definitions for every field in the MEDIQ dataset, including types, possible values, examples, and notes on edge cases.

---

## Original Fields

These fields are present in the raw data before AI enrichment.

### `question`

| Property | Value |
|----------|-------|
| Type | string |
| Required | yes |
| Max length | ~2000 characters |

The text of the user's query as submitted to the chatbot. The string is lightly cleaned (leading/trailing whitespace removed) but otherwise unmodified. Questions may be in English, Hindi (Devanagari script), Romanized Hindi, or a mix.

**Examples:**
- `"What are the visiting hours for the surgery ward?"`
- `"MBBS admission ke liye kya documents chahiye?"`
- `"डॉक्टर से मिलने का समय क्या है?"`

**Edge cases:**
- Some entries contain very short queries (1–3 words) that lack context on their own; the `is_followup` field indicates whether they are part of a longer session.
- Romanized Hindi queries are sometimes ambiguous and can appear to be broken English at a glance.

---

### `answer`

| Property | Value |
|----------|-------|
| Type | string |
| Required | yes |
| Max length | ~5000 characters |

The chatbot's response to the query. Answers are generated by the deployed AI chatbot and are included verbatim (after PII scrubbing). Answer quality varies; see the `answer_quality` enriched field.

**Examples:**
- `"Visiting hours are 4 PM to 6 PM daily. For ICU, please contact the nursing station."`

**Edge cases:**
- Some answers are templated fallbacks (e.g., "I'm sorry, I don't have information on that") — these typically receive `answer_quality: low`.
- Answers may include formatting artifacts from the original chat interface.

---

### `timestamp`

| Property | Value |
|----------|-------|
| Type | ISO 8601 datetime string |
| Required | yes |
| Precision | minute-level (seconds and milliseconds are zeroed) |
| Timezone | UTC |

The time at which the chatbot interaction occurred. Sub-minute precision is discarded as a privacy measure.

**Example:** `"2024-11-15T09:32:00Z"`

---

### `sessionId`

| Property | Value |
|----------|-------|
| Type | string (SHA-256 hash, hex-encoded, truncated to 16 chars) |
| Required | yes |

An anonymized session identifier. Entries sharing the same `sessionId` belong to the same conversation session. The identifier is not reversible to any user identity or device.

**Example:** `"sess_a3f9c2b1d4e70f88"`

**Edge cases:**
- A session can contain a single message or dozens.
- Sessions do not have fixed time boundaries; they are determined by the original chatbot's session management logic.

---

### `messageId`

| Property | Value |
|----------|-------|
| Type | string |
| Required | yes |
| Uniqueness | globally unique within the dataset |

A stable, unique identifier for each question–answer pair. Use this field when referencing specific entries in issue reports or research.

**Example:** `"msg_00412"`

---

## AI-Enriched Fields

These fields are added by the automated enrichment pipeline using the Kimi K2 model via the Groq API. They should be treated as model-generated annotations, not ground truth.

---

### `detected_language`

| Property | Value |
|----------|-------|
| Type | string (enum) |
| Values | `en`, `hi`, `hi-Latn`, `mixed` |
| Required | yes |

The language of the user's query as classified by the enrichment model.

| Value | Meaning |
|-------|---------|
| `en` | English |
| `hi` | Hindi in Devanagari script |
| `hi-Latn` | Hindi written in Latin (Roman) script — Romanized Hindi |
| `mixed` | A query that contains significant portions of two languages or scripts |

**Edge cases:**
- Very short queries (1–3 words) may be misclassified; `corrected_language` applies a heuristic post-pass.
- Technical or medical terms in English embedded in an otherwise Hindi sentence are classified as `hi` or `hi-Latn`, not `mixed`, unless the English content is substantial.

---

### `corrected_language`

| Property | Value |
|----------|-------|
| Type | string (enum) |
| Values | Same as `detected_language` |
| Required | yes |

A post-heuristic correction of `detected_language`. The most common correction is Romanized Hindi (`hi-Latn`) being initially classified as `en` by the model.

When no correction is needed, `corrected_language` equals `detected_language`.

---

### `intent`

| Property | Value |
|----------|-------|
| Type | string (enum) |
| Required | yes |

The classified intent of the user's query. Controlled vocabulary:

| Intent | Description |
|--------|-------------|
| `appointment_booking` | Requesting to book, reschedule, or cancel an appointment |
| `opd_info` | Questions about outpatient department timings, locations, or procedures |
| `admission_inquiry` | Queries about academic admissions (MBBS, MD, nursing, etc.) |
| `test_results` | Asking about lab test results, reports, or diagnostic procedures |
| `doctor_info` | Asking about a specific doctor's availability, specialization, or contact |
| `ward_info` | Questions about hospital wards, rooms, or inpatient services |
| `fee_structure` | Queries about fees for academic programs or hospital services |
| `emergency_services` | Queries related to emergency or urgent care |
| `general_hospital_info` | General questions about the hospital or university |
| `directions_location` | Questions about how to reach a department, building, or facility |
| `academic_info` | Questions about courses, examinations, results, or academic calendar |
| `grievance` | Complaints or expressions of dissatisfaction |
| `greeting` | Greetings or conversational openers with no substantive query |
| `other` | Queries that do not fit any of the above categories |

---

### `medical_relevance`

| Property | Value |
|----------|-------|
| Type | float |
| Range | 0.0 to 1.0 (inclusive) |
| Required | yes |

A continuous score representing how clinically or medically relevant the query is. A score of 1.0 indicates a query that is directly about clinical medicine, diagnosis, treatment, or symptoms. A score of 0.0 indicates a query with no medical content (e.g., parking directions).

Administrative queries (fee structure, admissions) typically score in the 0.1–0.4 range. Clinical queries score 0.7–1.0.

---

### `sentiment`

| Property | Value |
|----------|-------|
| Type | string (enum) |
| Values | `positive`, `neutral`, `negative` |
| Required | yes |

The sentiment of the user's query text. Most queries are neutral (informational requests). Negative sentiment often corresponds to grievances or expressions of frustration.

---

### `answer_quality`

| Property | Value |
|----------|-------|
| Type | string (enum) |
| Values | `high`, `medium`, `low`, `uncertain` |
| Required | yes |

The model's assessment of whether the chatbot's answer is complete, accurate, and contextually appropriate.

| Value | Meaning |
|-------|---------|
| `high` | Answer directly addresses the query with specific, useful information |
| `medium` | Answer is partially relevant or somewhat vague |
| `low` | Answer is a fallback, off-topic, or clearly incomplete |
| `uncertain` | The model could not confidently assess quality |

---

### `topic_tags`

| Property | Value |
|----------|-------|
| Type | list of strings |
| Required | yes (may be empty list `[]`) |

Free-form subject tags assigned to the query. Tags are not from a fixed vocabulary; they describe the subjects mentioned in the query. A query may have zero, one, or several tags.

**Examples:** `["OPD", "timing"]`, `["MBBS", "admission", "eligibility"]`, `["emergency", "ambulance"]`

---

### `user_type`

| Property | Value |
|----------|-------|
| Type | string (enum) |
| Values | `student`, `patient`, `visitor`, `staff`, `unknown` |
| Required | yes |

The inferred type of user based on contextual cues in the query. This is a model inference and may not always be accurate.

| Value | Inference cues |
|-------|----------------|
| `student` | Mentions of courses, exams, results, admissions, hostel |
| `patient` | Mentions of symptoms, treatment, doctor visits, test results |
| `visitor` | Mentions of visiting a patient, ward locations, timings |
| `staff` | Mentions of employee-specific processes; rare |
| `unknown` | Insufficient cues to classify |

---

### `english_translation`

| Property | Value |
|----------|-------|
| Type | string or null |
| Required | yes |

An English translation of the user's query. This field is populated only for queries where `corrected_language` is `hi`, `hi-Latn`, or `mixed`. For English queries, the value is `null`.

Translations are model-generated and may not be perfect, particularly for highly colloquial or domain-specific phrasing.

**Example:** Query `"OPD ka time kya hai?"` → `"What is the OPD timing?"`

---

### `is_followup`

| Property | Value |
|----------|-------|
| Type | boolean |
| Values | `true`, `false` |
| Required | yes |

Indicates whether the query appears to be a follow-up to a previous message in the same session. Detection is based on session context: a query is flagged as a follow-up if it uses pronouns, demonstratives, or references that only make sense given a prior query in the same `sessionId`.

**Example:** After asking "Who is the head of orthopedics?", a follow-up might be "What are his timings?" — this would be flagged `true`.

**Edge cases:**
- First messages in a session are always `false`.
- For sessions with a single message, `is_followup` is always `false`.
- Detection accuracy is lower for very short follow-up queries.
